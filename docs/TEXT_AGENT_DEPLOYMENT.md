# Развёртывание ветки с текстовым агентом

Ветка: `codex/text-agent-integration`. Основа: `production-current`.

## Что добавлено

В авторизованном интерфейсе появляется кнопка «Помощник». Первый сценарий — создание арендатора по тексту, уточнение обязательных полей, предпросмотр и явное подтверждение. Запрос выполняется с текущим JWT пользователя; принадлежность аккаунту определяет Rental CRM. После успеха виджет обновляет данные приложения.

Используется DeepSeek `deepseek-flash`. Текст и черновик отправляются DeepSeek; JWT пользователя туда не передаётся. API-ключ живёт только в окружении backend. В репозитории ключа нет.

Ветка самодостаточна: Docker собирает Java-библиотеку из `backend/vendor/text-agent`, React-пакет устанавливается из `frontend/vendor/text-agent-react-0.1.1.tgz`. Исходники React-пакета также сохранены в `frontend/vendor/text-agent-react-source`. Внешняя публикация пакетов и соседний репозиторий для сборки не нужны.

## Порядок развёртывания на существующем сервере

1. В каталоге Rental CRM проверьте незакоммиченные изменения и переключитесь на ветку:

```sh
git status --short
git fetch origin
git switch --track origin/codex/text-agent-integration
```

Если локальная ветка уже создана, используйте `git switch codex/text-agent-integration` и `git pull --ff-only`.

2. **Сохраните текущий серверный `.env`** с настройками базы, шифрования и JWT. Не заменяйте его целиком файлом `.env.example`. Добавьте/обновите только параметры агента через редактор или используемое хранилище секретов:

```dotenv
TEXT_AGENT_ENABLED=true
AGENT_API_KEY=<настоящий ключ DeepSeek, только на сервере>
AGENT_MODEL_ENDPOINT=https://api.deepseek.com/chat/completions
AGENT_MODEL=deepseek-flash
```

Установите права `chmod 600 .env`. Не добавляйте `.env` в Git. Compose остановится с понятной ошибкой, если AGENT_API_KEY не задан. Ключ не используется на этапе Docker build и не попадает в frontend или его build args.

3. Запустите сборку и обновление сервисов с сохранением существующего имени Compose-проекта и volumes:

```sh
docker compose -f docker-compose.yml config --quiet
docker compose -f docker-compose.yml up -d --build backend frontend
docker compose -f docker-compose.yml ps
```

Если на сервере используется `-p` или дополнительный production compose-файл, сохраните эти же параметры. Команды выше явно выбирают основной файл, чтобы не подхватить локальный `docker-compose.override.yml` с dev-портами. Существующие данные и схема базы не меняются этой интеграцией; миграций для агента нет. Не используйте `down -v`.

4. Откройте приложение, войдите в аккаунт и обновите страницу. Справа внизу должна появиться кнопка «Помощник».

## Проверка

- Напишите «Создай арендатора, ФИО: Тестовый Пользователь». Должен появиться запрос недостающего телефона.
- Укажите тестовый телефон, например `+15555550123`. Агент должен показать данные и кнопки «Подтвердить» / «Отменить».
- До подтверждения запись не создаётся. «Отменить» не создаёт запись.
- Подтверждайте только если хотите создать тестовую запись в этом аккаунте. После успеха арендатор появится в списке.
- Повторное нажатие подтверждения не отправляет тот же запрос повторно в пределах живой сессии.
- При сетевой ошибке после подтверждения сначала проверьте состояние и список арендаторов: операция могла выполниться.

Обычные тесты не вызывают облачную модель. Для отдельного живого smoke-test используйте инструкции исходной библиотеки; его REST-назначение — локальный тестовый сервер, а не база Rental CRM.

## Настройки

`SPRING_PROFILES_INCLUDE=text-agent` активирует профиль. `AGENT_TARGET_BASE_URL` в Compose указывает на `http://127.0.0.1:8080` внутри backend-контейнера; запрос идёт через существующую защиту REST API.

Для смены модели предусмотрены `AGENT_MODEL_ENDPOINT` и `AGENT_MODEL`. В `application-text-agent.yml` заданы DeepSeek options: `thinking.type=disabled`, `max_tokens=2048`. При переходе на другого провайдера проверьте поддерживаемые options.

Сейчас разрешена только `createTenant` из `agent-openapi.yaml`. Создание договоров и других сущностей не включено. Расширение требует явно добавить контракт и operationId в allowlist.

## Ограничения стенда

Сессии и результаты подтверждений хранятся в памяти **одного экземпляра backend**, до 30 минут бездействия; подтверждение действует 3 минуты. После перезапуска сессия теряется. Несколько реплик не поддержаны.

В Rental CRM ещё нет сохранения специальных agent-маркеров аудита и серверной обработки `Idempotency-Key`. При timeout/5xx результат может быть неизвестен: не повторяйте создание вслепую. Нет отдельного rate limiting, scoped agent-токенов и постоянного хранилища подтверждений. Это ветка для проверки MVP, а не завершённая production-система агента.

Чтобы выключить помощника, задайте `TEXT_AGENT_ENABLED=false` и пересоберите frontend/пересоздайте backend той же командой Compose. Ключ можно оставить в серверном `.env`: Compose в этой ветке требует его наличия даже при выключенном помощнике. Для полного отката вернитесь на исходную ветку и пересоберите оба сервиса, сохраняя существующие volumes и имя Compose-проекта.

## Локальная проверка исходников

```sh
mvn -f backend/vendor/text-agent/pom.xml clean install
mvn -f backend/pom.xml -Ptext-agent package
cd frontend
npm ci
VITE_TEXT_AGENT_ENABLED=true npm run build
```
