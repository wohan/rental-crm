# Продвижение RentCRM на рынок РФ и SEO-аудит

Дата: 2026-06-15

## 1. Вывод

RentCRM можно продвигать на рынке РФ, но текущий frontend больше похож на рабочий кабинет, чем на SEO-ориентированный сайт. Для платного трафика и первых продаж этого достаточно при наличии отдельного лендинга или demo-страницы, но для органического SEO нужно сделать публичную часть сайта: главная, страницы сегментов, страницы функций, сравнения, статьи и help center.

Что уже улучшено в приложении:

1. Добавлены базовые SEO meta tags в `frontend/index.html`.
2. Добавлены Open Graph/Twitter meta tags.
3. Добавлена JSON-LD разметка `SoftwareApplication`.
4. Уточнен title: `RentCRM — CRM для арендодателей`.
5. Добавлен `frontend/public/robots.txt` с разрешением индексации.

Главная проблема: React SPA с контентом, который появляется после JavaScript, хуже подходит для SEO, чем SSR/static marketing pages. Личный кабинет за логином не должен быть основной SEO-точкой входа.

## 2. Целевые клиенты и УТП

### Основные сегменты

1. Частные владельцы 5-50 квартир.
2. Управляющие посуточной и среднесрочной арендой.
3. Владельцы коммерческих помещений, складов, студий.
4. Небольшие управляющие компании.
5. Прокатные бизнесы с регулярными платежами и актами.

### Позиционирование

Коротко:

> RentCRM — простой кабинет для арендодателя: платежи, договоры, заявки, документы и доходность без Excel.

Для рынка РФ:

> CRM для арендодателей в России: рублевые тарифы, уведомления Telegram/SMS/WhatsApp, документы, платежный календарь, экспорт в Excel и контроль просрочек.

### Почему за это будут платить

1. Снижение просрочек за счет напоминаний.
2. Единая база объектов, арендаторов и договоров.
3. Быстрый контроль доходности по объектам.
4. Меньше ручного Excel и переписок.
5. Понятный free tier для 3 объектов и платный рост после него.

Темы, которые приводят целевую аудиторию:

## 5. SEO-аудит текущего приложения

### Что хорошо

1. `html lang="ru"` уже установлен.
2. Приложение быстрое и легкое.
3. Контент первого экрана есть в React UI.
4. Добавлены базовые meta tags и SoftwareApplication JSON-LD.

### Что плохо для индексации

1. Нет отдельного публичного маркетингового сайта.
2. Почти весь полезный контент создается JavaScript SPA.
3. Нет production `sitemap.xml`.
4. `robots.txt` добавлен, но после выбора домена нужно указать `Sitemap: https://<domain>/sitemap.xml`.
5. Нет canonical URL.
6. Нет отдельных индексируемых страниц под функции/сегменты.
7. Нет статей, FAQ, кейсов и comparison pages.
8. Нет публичной страницы тарифов вне личного кабинета.
9. Нет server-side rendering или static generation для SEO-страниц.

### Риск

Если продвигать только текущую SPA-страницу входа/регистрации, SEO будет слабым. Поисковики могут проиндексировать страницу, но ей будет трудно ранжироваться: мало текста, нет структуры, нет внутренних страниц, нет тематической глубины.

## 6. Рекомендации по архитектуре SEO

Лучшее решение:

1. Оставить текущий React app как `app.rentcrm.ru` или `/app`.
2. Сделать отдельный публичный сайт на Next.js/Astro/статическом React:
   - SSR/SSG;
   - sitemap;
   - robots;
   - canonical;
   - Open Graph;
   - schema.org;
   - blog/help center.
3. Все CTA ведут в текущий SaaS app.

Минимальное решение без отдельного проекта:

1. Добавить статичные HTML-страницы или prerender.
2. Сделать `/pricing`, `/features/*`, `/segments/*`.
3. Сгенерировать `robots.txt` и `sitemap.xml`.
4. Добавить canonical после выбора домена.

3. Добавить `robots.txt`.

5. Добавить canonical URL.
6. Сделать публичный landing с текстом 2500-4000 знаков.
7. Сделать страницу тарифов.

P1:

1. Страницы функций и сегментов.

3. FAQ schema.
4. Breadcrumb schema.

P2:
