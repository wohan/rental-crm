# Production readiness backlog

Дата: 2026-06-14

Цель: перевести RentCRM из MVP в полнофункциональный SaaS-продукт для промышленной эксплуатации на рынке РФ.

## 1. Уже реализовано в этой production-итерации

1. Health endpoint backend через Spring Boot Actuator.
2. Docker healthcheck для `backend` и `frontend`.
3. Базовые security headers на nginx:
   - `X-Frame-Options`;
   - `X-Content-Type-Options`;
   - `Referrer-Policy`;
   - `Permissions-Policy`;
   - `Content-Security-Policy`.
4. Базовый in-memory rate limit для регистрации и входа.
5. Audit log:
   - модель `audit_logs`;
   - миграция БД;
   - запись create/update/delete/status/settings/billing действий;
   - endpoint `/api/audit`;
   - frontend-раздел "Аудит".

## 2. P0: обязательно до реальной эксплуатации

### PRD-001. Production secrets и конфигурация

Что нужно:

1. Запретить production-старт с дефолтным `APP_JWT_SECRET`.
2. Вынести секреты платежей и уведомлений в secrets/env, а не хранить в UI в открытом виде.
3. Разделить профили `local`, `staging`, `production`.
4. Настроить CORS только на production-домен.

Статус: частично готово. Env уже есть, но жесткой проверки production-secret пока нет.

### PRD-002. HTTPS и reverse proxy

Что нужно:

1. Домен.
2. TLS-сертификаты.
3. Nginx/Caddy/Traefik перед docker-compose.
4. HSTS после запуска HTTPS.
5. HTTP -> HTTPS redirect.

Статус: не реализуется внутри приложения, требуется инфраструктура сервера.

### PRD-003. Резервное копирование и восстановление

Что нужно:

1. Ежедневный backup Postgres.
2. Retention 7/30/90 дней.
3. Проверка восстановления backup.
4. Документированный runbook восстановления.

Статус: не реализовано.

### PRD-004. Audit log

Что нужно:

1. Записывать действия пользователей.
2. Показывать последние действия владельцу/поддержке.
3. Не писать секреты и чувствительные данные в audit summary.

Статус: базовая версия реализована.

### PRD-005. Защита auth

Что нужно:

1. Rate limit входа/регистрации.
2. Блокировка грубого перебора.
3. Восстановление пароля.
4. Подтверждение email.
5. Возможность смены пароля.

Статус: rate limit реализован in-memory. Для нескольких backend-инстансов нужен Redis/WAF.

### PRD-006. Юридические документы и 152-ФЗ

Что нужно:

1. Политика обработки персональных данных.
2. Пользовательское соглашение.
3. Согласие на обработку ПДн.
4. Согласие на уведомления.
5. Регистрация оператора ПДн при необходимости.
6. Регламент удаления данных.
7. Хранение ПДн на инфраструктуре, допустимой для рынка РФ.

Статус: не реализовано в интерфейсе и документах пользователя.

### PRD-007. Платежи подписки

Что нужно:

1. Реальный checkout ЮKassa/CloudPayments/Robokassa.
2. Webhook оплаты.
3. Проверка подлинности webhook.
4. Автоматическое изменение тарифа после успешной оплаты.
5. Срок действия подписки.
6. Grace period.
7. Чеки/54-ФЗ через платежного провайдера.

Статус: checkout частично есть, webhook и жизненный цикл подписки не реализованы.

### PRD-008. Файловое хранилище документов

Что нужно:

1. S3-compatible storage: MinIO/Yandex Object Storage/Selectel.
2. Загрузка файлов из UI.
3. Signed URLs.
4. Ограничение доступа по accountId.
5. Антивирусная проверка.
6. Лимиты хранения по тарифам.

Статус: сейчас документы хранят только URL.
